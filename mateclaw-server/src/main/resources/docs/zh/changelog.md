以下为开发分支新增功能，不改写 3.1.0 发布范围，也未创建新的稳定版本：

- **员工配置复用**：同工作区原生员工快照、共享配置文档选择、新名称招聘与模板删除，保留三态绑定语义；自定义招聘严格检查依赖，内置模板兼容策略不变。当前不支持 DSH 快照或跨工作区导出。
- **协调员模式**：默认关闭的原生负责人职责限制，覆盖普通工具、动态入口、旧计划直接委派及主/备/汇总模型原生搜索；保留团队任务板和原有能力配置，执行中不能切换。

## 3.1.0：技能经验治理与执行可靠性

版本：**3.1.0**。发布日期：**2026-11-19**。本次说明覆盖 `v3.0.0` 之后的功能与修复；[3.0.0 执行架构升级](https://claw.mate.vip/docs/zh/releases/3.0.0)保留为历史记录。发行包以 [GitHub Releases](https://github.com/mateaix/mateclaw/releases) 为准。

3.1.0 让已经学到的技能经验更容易检查和撤回，让聊天、工具和渠道的执行结果更准确地呈现，并提高长上下文、历史媒体与故障恢复的稳定性。

### 技能经验与记忆

- **逐条撤回经验**：技能经验使用持久身份标识，可以撤回指定条目，避免只按显示位置识别经验。市场列表与经验面板在操作后刷新。
- **快照恢复预览**：恢复前展示将改变的技能内容与影响，确认后再执行恢复。
- **审阅结果更可信**：扫描不完整时拒绝把不完整结果作为通过依据；审阅操作后刷新结果。
- **安装可取消**：技能安装任务改为异步执行，取消与完成按任务生命周期处理。
- **附件完整性**：导入技能包时保留二进制附件；固定 `x-intel` 安装来源并移除远程 Shell 安装链路（#685）。
- **精确记忆编辑**：保留未编辑的章节内容，异步保存与删除绑定到发起操作时的记忆对象，避免切换会话或条目后影响其他内容。

技能 Reflection 与 routine mining 的默认开关保持关闭，需按工作空间策略显式启用；经验治理改进不自动扩大技能执行权限。

### 聊天状态与工具结果

- 选择回答中的文字后，可引用到后续提问草稿；浏览器标题与 favicon 显示会话和运行状态。
- Shell 工具显示简短的命令意图标题，实际执行参数不变；命令失败按真实退出结果展示，历史失败记录也能正确渲染。
- 原生循环的工具事件只发布一次；修复片段消息列表的 DOM 容器，保持消息展示与定位正常（#683）。
- 输出达到上限时保留“未完成”状态，避免把不完整回答当作成功；停止原生流式回合后仍保留已报告的 token 用量。
- 用量列表按最新日期优先展示；用户可见回答的语言指导保持一致（#679）。

### 模型、上下文与执行恢复

- 保存模型及供应商配置前校验生成参数，提前拒绝非法值；增加 Azure 统一 OpenAI 端点支持，并保留端点所需查询参数。
- 同一供应商的并发请求受到共享限额约束，冷却与忙碌状态有更清楚的故障说明；故障转移使用实际备用模型身份与供应商遥测（#676）。
- 统一上下文组装并保留已压缩历史。遇到本地上下文溢出时先尝试恢复，避免过早拒绝历史记录（#684）。
- 请求副本中缩小过大图片、过滤空媒体；请求过大时可省略历史媒体，保留已持久化的原始附件。
- 限制技能概览与发现内容，保留验证证据；新建员工的默认迭代预算由 10 提升至 100，已有员工保留其配置，并解释达到上限的运行（#672、#674）。
- 工具超时覆盖在调用中生效，未完成的计划步骤会中止；计划总结可恢复，最终答复检查失败明确呈现（#672、#681）。
- 团队 Lead 重试仍受累计派发预算限制，避免每次重试重新获得整份预算（#688）。
- H2 中断写入恢复与认证会话持久化得到加固（#681）。

### Wiki、文档与渠道

- **单个来源提取实体**：在 Wiki 原始资料面板中，对指定文档发起实体提取（#673）。
- **答案与引用一致**：多次检索后保留答案并对齐引用；中断的文档分析可恢复，空子会话不再挤入普通历史列表（#683、#686）。
- **文档交付**：生成 DOCX 后继续推理，避免把工具完成误当作整个任务完成（#687）；修复 Markdown 表格导出的值保留与边界情况，文本编辑保留原有换行风格。
- **消息投递**：钉钉长 Markdown 分段发送并校验投递确认；飞书附件上传保留可读文件名；Team 与 A2A 事件流增加防代理缓冲处理。

### DeepSeek Harness、桌面端与部署

DSH 新增可选候选 **`0.2.2-rc.1`**，需要 **Node.js 24.9+（24.x）**。受管理安装的默认版本仍是 **`0.2.0-rc.1`**；升级 MateClaw 不会自动把已有 DSH 配置切换到候选版本。

候选升级保留运行时 home、配置与回滚代际，恢复文件观察保护并绑定模型容量配置。本机 macOS arm64 原生模式已通过安装、SDK 握手、真实聊天及 Bash 调用检查；Linux/Windows、持久 V3→V4 历史迁移、多小时耐久与生产回滚不在这些检查的覆盖范围内。macOS Docker 共享目录的 Landlock `EACCES` 限制仍存在，详见 [DSH 接入](./deepseek-harness)。

桌面端修复多平台打包，并加固 macOS JAR 内嵌原生二进制的签名、公证与打包流程；能否发布签名安装包仍取决于对应平台产物、证书与验证结果。

既有受管理部署的离线升级流程增加了升级前备份、试迁移、搜索健康检查，以及备份符号链接和文档路由处理。这些是面向对应部署环境的运维改进，使用范围以部署方案为准。

### 升级与验证

1. 升级前备份数据库、workspace、插件、`.env` / `.env.local` 和 DSH 运行时目录。保留原有 JWT 密钥，避免既有登录 token 失效。
2. 源码开发从仓库根目录运行，先安装 `mateclaw-plugin-api`，再按[贡献指南](./contributing)显式设置根目录 `data/` 数据库与工作空间路径；前端在 `mateclaw-ui/` 启动。
3. 正常执行 Flyway 校验，不修改已应用的迁移脚本。依赖升级本身不要求切换数据库引擎；已有 MySQL 部署不能直接套用 PostgreSQL Compose 期待自动迁移数据。
4. 升级后核对模型就绪、文本回答、工具结果、历史消息、取消后续聊，以及实际使用的渠道。需要回滚时使用升级前备份与对应旧版本。

依赖升级验收中，后端及 Mem0 插件共 **6,994 项测试，零失败，64 项按条件跳过**；前端 **518 项测试**及生产构建通过。真实模型验证覆盖文本、一次 Bash 工具执行、历史延续、流式取消、同一会话恢复与消息持久化。跳过项主要依赖外部数据库、专用 DSH 环境或平台条件，不代表对应环境已完成认证。
